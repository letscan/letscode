Why LetsCode

Trust it with the boring parts.
All night, if you want.

Most agents stop to ask permission every thirty seconds. LetsCode runs unattended inside boundaries you define — overnight refactors, bulk lint fixes, PR auto-review — without going off the rails.

01

True automation, trusted execution

Three security presets — safe, default, risk — plus fine-grained custom rules. Set the rules once; the agent works alone, safely.

$ letscode --preset safe \ "review PR #142" # read-only $ letscode --preset risk \ "migrate db schema" # full access
02

AgentCard: tailor and run

Define a ready-to-use agent — tools, MCP servers, skills, permissions — in one Markdown file. No code, no framework. Just a card and a --as flag.

$ letscode --as Review \ "review tools/runner.py" $ letscode --list-agents
03

Unix-composable multi-agent

Chain agents at the shell with pipes, or let the main agent delegate sub-agents itself. Build any workflow you can imagine — Explore → Plan → Review.

$ letscode --as Explore \ --event-stream "..." | \ letscode --as Plan "..."
Features

Small harness. Serious machinery.

Everything an agent needs to operate on a real codebase — nothing it doesn't.

⌁

Any LLM

Any OpenAI-compatible API: GLM, DeepSeek, Qwen, GPT, Gemini, or local models. Switch with one config line — env vars override the file when you need them to.

⛨

OS-level sandbox

macOS Seatbelt profiles enforce the boundary at the kernel level, not by prompting. Secret paths (.ssh/, .aws/, .env) are blocked on every preset.

◈

MCP built in

Connect stdio / HTTP / SSE MCP servers. Tools are auto-discovered and merged in at startup.

✦

Skills

Write your team's commit or review workflow as a SKILL.md, invoke it with a single command.

⑂

Sub-agents

Delegate searches and sub-tasks to a spawned agent so the main context stays clean.

◉

Vision proxy

Text-only model? Set a vision_model and images are auto-routed and described in text.

⌗

JSON event stream

--event-stream emits structured JSONL — pipe it into other tools, dashboards, or agents.

≡

Session & context control

Sessions persist across restarts. /compact, /new, /undo keep context in shape.

✎

Project rules that stick

Follows the AGENTS.md convention — your coding standards and workflow rules take effect automatically, every run. Workspace-aware: logs, sandbox boundaries, and environment context bind to --workspace.

↯

Prompt-cache aware

Auto mode for DeepSeek / GLM ≥ 4.6, explicit cache_control markers for Qwen / DashScope. The per-turn footer shows tokens with cache hit rate — 2.7k tokens (99% cached).

AgentCards

One Markdown file.
One flag. A specialist.

An AgentCard bundles a system prompt, tool allowlist, MCP servers, skills, and a security preset. Drop it in agents/, run it with --as. Ships with four built-in cards: Explore, Plan, Review, SetupZed.

  • No code, no framework — frontmatter + prose is the whole spec
  • Pair preset: safe with a narrow allowWrite to carve out exactly one writable file
  • Project-level cards sit next to your code, versioned with it
agents/Refactorer.mdagent card
---
name: Refactorer
tools: [Read, Edit, Grep, Glob]
mcp_servers: [playwright]
skills: [refactor]
preset: default
---

You are a refactoring specialist.
Extract services, remove duplication,
never change behavior.

# then:
$ letscode --as Refactorer \
    "extract a UserService from app.py"
Editor integration

CLI-first, not CLI-only.

When you want an interactive session, LetsCode speaks the Agent Client Protocol — the open standard adopted by Zed and a growing ecosystem of editors. One server, any compatible client, zero lock-in.

  • letscode-acp ships a built-in ACP server over stdio
  • Sessions persist across restarts — list, load, resume
  • Built-in setup cards write your editor config for you
terminalacp
# Zed — built-in agent writes .zed/settings.json for you
$ letscode --as SetupZed

# JetBrains
$ letscode --as SetupJetbrains

# or run the ACP server directly
$ letscode-acp -c config.json
  → speaking ACP over stdio …
Security

Boundaries enforced by the OS,
not by the prompt.

Presets cover the common cases; custom rules tighten or open up any of them. Rules use most-specific-wins: a precise allow overrides a broad deny, ties break to deny.

PresetReadWriteCommandsBest for
safe global blocked blocked CI/CD auto-review, audits
default global workspace + /tmp whitelisted Everyday dev work, overnight refactors
risk global global all allowed Migrations, full-system tasks

// .ssh/ · .aws/ · .gnupg/ · .env are blocked on every preset, always.

Install

Up and running in thirty seconds.

One script. It installs uv if you're missing it, then LetsCode as a global tool. Requires Python 3.11+.

install — zsh
$ curl -fsSL https://raw.githubusercontent.com/letscan/letscode/main/scripts/install.sh | sh ✓ uv ready · ✓ letscode installed · ✓ on PATH $ letscode "add a /health endpoint to app.py"
STEP 01

Install

Run the one-liner, or uv tool install git+https://github.com/letscan/letscode.git.

STEP 02

Configure

cp config.example.json config.json and drop in any OpenAI-compatible API key.

STEP 03

Prompt

letscode "your prompt here" — it loops, calls tools, and finishes the job.
