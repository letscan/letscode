Why LetsCode

Automation you can actually trust

Set the rules once. Then let the agent run unattended — overnight refactors, bulk fixes, PR review — without watching over its shoulder.

True automation, trusted execution

No more step-by-step approvals. Three sandbox presets cover most cases out of the box — and custom rules tighten or open up any of them.

safe · read-only default · workspace risk · full access
# read-only CI/CD review letscode --preset safe "review PR #142" # overnight refactor letscode --preset default "refactor auth/ to async" # full migration letscode --preset risk "migrate db schema to v2"

AgentCard

Define a ready-to-use agent — tools, MCP, skills, permissions — in one Markdown file, run it with --as.

# agents/Refactorer.md name: Refactorer tools: [Read, Edit, Grep, Glob] mcp_servers: [playwright] preset: default

Composable agents

Chain agents at the shell, Unix-style — or let the main agent delegate sub-agents itself.

letscode --as Explore ... \ | letscode --as Plan ... \ | letscode --as Review ...

Plug into any editor — zero lock-in

LetsCode speaks the Agent Client Protocol, the open standard adopted by Zed and a growing ecosystem. One server, any compatible client.

Zed JetBrains Any ACP client
# Zed — auto-writes .zed/settings.json letscode --as SetupZed # JetBrains letscode --as SetupJetbrains

Security

Sandboxed by default, adjustable to the job

Three presets map directly to how much trust a task needs. Secret paths are always blocked — on every preset.

PresetReadWriteCommands
safeGlobalBlockedBlocked
defaultGlobalWorkspace + /tmpWhitelisted
riskGlobalGlobalAll allowed

Secrets (.ssh/ · .aws/ · .gnupg/ · .env) blocked on all presets.

# config.json — most-specific-wins { "rules": { "allowRead": ["src/**", "tests/**"], "denyWrite": ["secrets/**"], "allowCmd": ["ls", "cat", "git"], "denyCmd": ["rm -rf"] } }

A more specific allow (e.g. plan.md) overrides a broader deny — so a card can pair safe with a narrow write carve-out.

Install

One line. Then go.

Requires Python 3.11+. The one-liner installs uv if missing, then LetsCode as a global tool.

01 · One-liner

Install globally

Bootstraps uv and installs letscode.

$ curl -fsSL https://raw.githubusercontent.com/letscan/letscode/main/scripts/install.sh | sh
02 · Manual

Clone & install

For development, or install from the repo as a global tool.

$ git clone https://github.com/letscan/letscode.git $ cd letscode $ uv sync # development # — or — $ uv tool install git+https://github.com/letscan/letscode.git
Configuration

Point it at any model

Create a config from the template, drop in your API key, and you're running. Works with any OpenAI-compatible API.

# config.json { "default_model": "glm-5-turbo", "providers": { "zhipu": { "base_url": "https://open.bigmodel.cn/api/coding/paas/v4", "api_key": "YOUR_API_KEY", "models": [ { "model": "glm-5-turbo", "max_tokens": 200000 } ] } } }
# env vars override the file export OPENAI_API_KEY="YOUR_API_KEY" export OPENAI_BASE_URL="https://open.bigmodel.cn/api/coding/paas/v4" # then: name a task letscode "add a /health endpoint to app.py"
